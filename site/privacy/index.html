PODWIN / PRIVACY

Privacy policy

Last updated: November 27, 2026

Who publishes PodWin

PodWin is published on the Microsoft Store under the MightyB handle by Brian Swiger (mightybs.com). The package identity is MightyB.PodWin. This policy describes the PodWin desktop app and this website.

What PodWin accesses locally

PodWin reads local runtime versions, WSLc session names and state, container and image metadata, supported network and volume metadata, and requested output needed to show inventory, details, logs, or sandbox status. Names, paths, image references, and output can identify people or contain sensitive information.

PodWin has zero app telemetry. It does not include usage analytics, advertising, behavioral tracking, or remote crash reporting.

PodWin keeps local, redacted, size-bounded diagnostics. Diagnostic files contain fixed operation and failure events and numeric HRESULTs. They do not contain credentials, environment values, inspect payloads, command input or output, or container logs. Diagnostic files remain on your device and are never uploaded.

What PodWin stores and where

PodWin saves appearance and window settings and, if you choose them, Agent Sandbox defaults. It does not save container output or log snapshots automatically.

The Direct build stores settings at %LOCALAPPDATA%\PodWin.Settings.Direct\settings.json and redacted diagnostics at %LOCALAPPDATA%\PodWin\logs. Direct settings survive uninstall. Direct uninstall removes its diagnostic logs with the app installation data.

The Store build stores settings and diagnostics in the package LocalFolder. Windows removes that package-local data when the Store app is reset or uninstalled.

Owned-session and Agent Sandbox storage is separate from package and settings data:

  • Direct owned sessions use %LOCALAPPDATA%\PodWin.Sessions.Direct.
  • Store owned sessions use %USERPROFILE%\.podwin\PodWin.Sessions.Store.
  • Direct Agent Sandbox data uses %LOCALAPPDATA%\PodWin.Sandboxes.Direct.
  • Store Agent Sandbox data uses %USERPROFILE%\.podwin\PodWin.Sandboxes.Store.

These retained disks and ownership records survive the relevant session termination or app exit, and Direct uninstall. Store owned-session and sandbox data also survive uninstall and Reset. PodWin never deletes owned-session data, and it never cleans up Agent Sandbox directories automatically. Destroy removes a sandbox's container but not its retained disk or ownership record. Starting with PodWin 1.1, you can permanently delete one stopped sandbox's retained data with Remove retained data on the Agent Sandboxes page. PodWin deletes it only after you confirm a dialog that names the sandbox, its folder, its files, and their size, and only after it checks that it created that folder, that nothing is using it, and that WSLc no longer lists that sandbox. It deletes only that sandbox's ownership record, disk files, and folder. It never follows links, never touches another folder, and never removes the .podwin folder or the sandbox storage folder itself. Deleted data does not go to the Recycle Bin and cannot be recovered. An agent's MCP request cannot start this removal. Local diagnostics record only that a removal finished, finished partly, or failed, with a numeric error code; they never record the sandbox ID, folder path, or size.

The .podwin directory under the classic user profile roams with classic roaming profiles unless an administrator excludes it with ExcludeProfileDirs.

The Direct build can add a per-user PodWin startup value under HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run, but only after your confirmation in Settings. Its uninstall callback removes only that value. The optional Store Start at sign-in choice is a Windows startup task; Windows stores and manages that state. PodWin keeps no separate copy of the choice.

To remove a stopped sandbox's retained data, use Remove retained data on the Agent Sandboxes page. To remove retained owned-session data, or sandbox data that PodWin cannot verify, follow the exact Remove retained PodWin data steps. Close PodWin, verify through a read-only WSLc session list that the exact registration is absent, and remove only the exact session or sandbox folder. Never remove the .podwin root or an unrelated session or sandbox folder.

Network connections

The Direct build checks for stable releases against GitHub Releases only when you request it. It does not poll in the background or apply updates automatically. A download requires your confirmation, and GitHub can receive request metadata such as your source IP address.

The Store build uses Microsoft Store-managed updates and excludes the Direct update code and Velopack. It performs no in-app update check.

Connecting to or changing a WSLc session is a deliberate action. PodWin shows a confirmation before an inventory read can activate an idle session and requires explicit consent before it creates, terminates, or otherwise mutates session state. Session and sandbox operations requested by an AI agent are not user consent.

When you consent to an image pull, PodWin sends the exact image reference to the chosen public registry only after consent and only when the PodWin-owned session is confirmed Running. The registry receives associated network information such as your source IP address. This release does not support private registry credentials. PodWin does not send settings or diagnostics to the registry.

Network list and inspect reads use the local WSLc runtime, are read-only, and require a channel-owned session you explicitly confirmed as Running. PodWin does not enable these reads for an external session, perform a network mutation, or change host network configuration.

Agent Sandboxes are available in both the Direct and Store builds. Creating a sandbox pulls the requested public image after consent. The sandbox containers run with networking disabled and deny-all network policy; PodWin provides no destination allowlist beyond deny-all.

The local MCP server is opt-in and its listener is off by default. Enable it only for the selected launch. While enabled, PodWin listens only on a local named pipe secured to the current Windows account. The Store package exposes a podwin-mcp.exe alias, and the Direct build uses a separate PodWin.McpServer.exe executable. Neither the listener nor the sidecar opens a network listener. Create, execute, and destroy requests require fresh consent in the app; a read-only sandbox list request does not require consent.

When you choose to open a published container port, PodWin asks Windows to open the link in your default browser. PodWin does not itself request the link.

WSL and container workloads can make their own network requests. PodWin's local-first design does not control or prevent those requests.

Microsoft's own privacy statement covers WSL, Windows, and the Microsoft Store: Microsoft Privacy Statement.

Your controls

You choose what PodWin displays and what information you copy or share. A log snapshot leaves PodWin only when you choose Copy or Save. Copy puts the snapshot on the Windows clipboard. Save writes it to a file that you choose in the Windows save dialog.

You can change appearance and startup preferences in Settings. You can enable MCP only for a launch and disable it later. You can remove Direct settings and logs manually while PodWin is closed.

Store settings and logs remain in package LocalFolder until Windows removes them through reset or uninstall. The external owned-session directory requires manual removal after the exact WSLc registration is absent. You can remove a stopped Agent Sandbox's retained data in the app with Remove retained data, or manually. PodWin provides the exact steps on this website and in the app's User Guide.

If you email support at support@podwin.app, the information you choose to send leaves your device. Registries and container workloads can have their own privacy policies.

Children

PodWin is not directed to children. A parent or guardian who allows a child to use the app should review local container data and anything copied or sent to another service.

Changes to this policy

When PodWin changes how it handles data, MightyB may update this policy. The Last updated date at the top shows the latest revision.

Support

PodWin requires Windows 11 22H2 or later on x64 with Microsoft WSLc 3.0.3 or 3.0.4 installed separately.

Troubleshooting

  • WSLc is missing, access is denied, or discovery fails: Check that %PROGRAMFILES%\WSL\wslc.exe exists and that the installed runtime is supported. PodWin does not search other locations or install, update, or elevate WSLc. Fix the specific prerequisite reported by Discover, then retry.
  • No sessions are listed: Discovery found no existing sessions; it does not create one. Choose Create session only if you want PodWin's owned session, review the dialog, and confirm it.
  • A runtime, session, or inventory read fails: Return to Discover, choose the exact intended session, and confirm Connect again. A timeout, canceled read, or other error is not an empty inventory.
  • PodWin reports a startup or storage-access problem: Read the surfaced path and error. Check local storage permissions and available space, and repair only the exact path PodWin names. Recovering PodWin does not require deleting environment disks, running wsl --shutdown, or changing WSL configuration.
