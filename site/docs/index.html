PODWIN / DOCUMENTATION

A good place to begin.

PodWin 1.0 is a native Windows 11 app for discovering and managing WSLc containers, with opt-in local Agent Sandboxes for coding tools.

Available from the Microsoft Store. PodWin 1.0 is an x64 app for Windows 11 22H2 or later with Microsoft WSLc 3.0.3 or 3.0.4.

What PodWin 1.0 does

Discover a WSLc session, confirm the connection, and browse its containers and images. In a session PodWin owns, you can also pull an image, check whether the session is running, or terminate it. PodWin asks before it acts.

Use the command palette (Ctrl+K) to get around, or open the user guide from Settings > About PodWin. Settings also lets you choose light, dark, or system appearance.

A detected CLI does not prove that the WSL components or an existing session are healthy. PodWin can still be used for dependency diagnosis without a session.

Build from source

Building from source is for contributors with access to the project repository. Store users should install PodWin from the Microsoft Store. Run these commands in a Windows PowerShell terminal.

POWERSHELL / DEVELOPMENT
git clone https://github.com/swigerb/PodWin.git
cd PodWin
dotnet test tests\PodWin.Core.Tests\PodWin.Core.Tests.csproj
dotnet build src\PodWin.App\PodWin.App.csproj
& .\src\PodWin.App\bin\Debug\net10.0-windows10.0.26100.0\win-x64\PodWin.exe

The project uses public nuget.org packages. No Visual Studio extension is required. If a restore fails, see the repository README for supported troubleshooting; never disable TLS verification.

Your first connection

  1. Discover. Open PodWin and discover existing WSLc sessions. Discovery does not create a session or change global WSL settings.
  2. Select. Choose the exact existing session you want to inspect. PodWin does not silently fall back to a default session.
  3. Confirm. Review the connection prompt. Reading inventory can activate an idle session's VM, so connecting is a deliberate action.
  4. Inspect. Read the container or image inventory. Where logs are supported, open a container's Logs tab and choose Follow to start reading or Stop to finish.

Logs can contain secrets. Opening the Logs tab does not start a read. Check the text before copying it, and leave private logs out of public issues.

Troubleshooting

WSLc is missing or discovery fails

Check that the required WSLc runtime is installed at the standard Microsoft WSL location. PodWin does not install it for you. Follow the official WSL container guidance and use the exact diagnostic shown in the app.

No sessions or containers are listed

Discovery lists existing WSLc sessions; it does not create one. If you need a new session, use Create session to create the one PodWin owns. Otherwise, connect to the existing session you intended to inspect. A reported error is a failed read, not evidence that the session is empty.

A read is canceled, times out, or reaches its output limit

The process boundary deliberately caps execution time and output. Read the surfaced error and retry only when appropriate. Do not interpret a canceled or truncated operation as a complete inventory.

Remove retained PodWin data

PodWin retains owned-session disks and ownership records outside the app. Agent Sandbox disks and ownership records are also retained. Removing this data manually requires care: close or uninstall PodWin, then verify the exact WSLc registration is absent before deleting any files.

Direct owned sessions

  1. Close or uninstall PodWin.
  2. Use a read-only WSLc session list to confirm that PodWin is not registered. If it is still registered, do not remove any files; use the supported WSLc process to remove only that registration, then repeat the read-only list.
  3. After PodWin is absent, remove only the %LOCALAPPDATA%\PodWin.Sessions.Direct folder.

Store owned sessions

  1. Close or uninstall PodWin.
  2. Use a read-only WSLc session list to confirm that PodWinStore is not registered. If it is still registered, do not remove any files; use the supported WSLc process to remove only that registration, then repeat the read-only list.
  3. After PodWinStore is absent, remove only the %USERPROFILE%\.podwin\PodWin.Sessions.Store folder.

Direct Agent Sandboxes

  1. Close or uninstall PodWin.
  2. Use a read-only WSLc session list to confirm that the sandbox's exact <32-hex ID> registration is not present. If it is still registered, do not remove any files; use the supported WSLc process to remove only that exact registration, then repeat the read-only list.
  3. After that exact registration is absent, remove only the exact <32-hex ID> folder at %LOCALAPPDATA%\PodWin.Sandboxes.Direct\<32-hex ID>. Never remove the whole .podwin directory or another session's directory.

Store Agent Sandboxes

  1. Close or uninstall PodWin.
  2. Use a read-only WSLc session list to confirm that the sandbox's exact <32-hex ID> registration is not present. If it is still registered, do not remove any files; use the supported WSLc process to remove only that exact registration, then repeat the read-only list.
  3. After that exact registration is absent, remove only the exact <32-hex ID> folder at %USERPROFILE%\.podwin\PodWin.Sandboxes.Store\<32-hex ID>. Never remove the whole .podwin directory or another session's directory.

Never remove the .podwin root, a PodWin owned-session root, or an unrelated sandbox folder as a settings reset or troubleshooting shortcut.

Repair retained storage access

The retained session path named by PodWin does not have the required private access policy. PodWin refuses to open or create retained session data at that path. For Direct, the error can name %LOCALAPPDATA%\PodWin.Sessions.Direct, its storage directory, storage\storage.vhdx, or owner-v2.json. For Store, it can also name %USERPROFILE%\.podwin, %USERPROFILE%\.podwin\PodWin.Sessions.Store, its storage directory, storage\storage.vhdx, owner-v2.json, or a private sandbox root. Repair only the file or folder named in the error message:

  1. Close PodWin.
  2. In File Explorer, open Properties > Security > Advanced for the path named in the error message. Confirm that the owner is the signed-in Windows account.
  3. Disable inherited permissions by removing all inherited permissions. Leave Replace all child object permission entries with inheritable permission entries from this object cleared.
  4. For a VHDX file named in the error, keep the Administrators entry only if it is an Allow entry, and remove every Deny entry. The validator rejects any Deny entry. Remove every other entry, then give the signed-in Windows account Full control. For a folder or owner-v2.json, remove every other access entry, including any Deny entry, and give the signed-in Windows account Full control. On a directory, retain that permission for this folder, subfolders, and files.
  5. Apply the change and reopen PodWin. Do not add Everyone, Users, or broader access.

Do not delete or replace a Direct or Store ownership record, a retained sandbox ownership record, or a VHDX as an access-repair step. If another account or process legitimately owns data at the named path, stop and have the profile administrator confirm the repair.

Privacy and your environment

PodWin sends no app telemetry and does not automatically save container log output. It keeps bounded, redacted diagnostic logs on your device; find them in Settings > Privacy and diagnostics. WSLc is a separate Microsoft runtime with its own data handling.

This website has no analytics, advertising, tracking cookies, third-party fonts, or embedded third-party scripts. The theme control operates in the current page and URL; it does not store a tracking identifier. GitHub Pages serves the site and may process request information under GitHub's privacy statement. Links to GitHub and other resources take you to those providers.

To remove retained owned-session or Agent Sandbox data, follow Remove retained PodWin data. The steps include the required WSLc registration checks.

This describes current behavior. Read the public privacy policy for the distribution policy and storage details.
